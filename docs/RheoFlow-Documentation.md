# RheoFlow — Technical Documentation

This document describes how the RheoFlow simulator handles variables, units, conversions, and calculations. It is derived from the source code (`app.js`, `index.html`) and covers both the homogeneous-duct and non-homogeneous-duct modes.

---

## 1. Overview and Architecture

RheoFlow is a single-page static web application. It has no backend; all calculations run in the browser.

| File | Purpose |
|------|---------|
| `index.html` | DOM structure, controls, metric/dashboard layout, equation placeholders. |
| `styles.css` | Visual styling, responsive layout, accessibility scaling variables. |
| `app.js` | All simulator logic: unit conversion, rheology, solvers, visualization, interactivity. |
| MathJax (CDN) | Renders the LaTeX equation strings generated by `updateEquation()`. |

### Core assumptions

The displayed models assume **incompressible, steady, laminar, axisymmetric, fully developed flow with no wall slip**. Equations are expressed in SI internally and rendered in SI in the equation panel. Inputs and outputs can be shown in a user-selected unit system.

All internal computation uses SI. The `defaults` object stores the fallback SI values used when an input is invalid:

| `viscosity` | `0.1` Pa·s | Default Newtonian/Bingham viscosity `μ`. |
| `consistency` | `0.001` Pa·sⁿ | Default consistency index `H`. |
| `flowIndex` | `0.65` | Default power-law index `n`. |
| `yieldStress` | `0.6` Pa | Default yield stress `τ₀` (0 for Newtonian/Power-Law; 0.5 for Bingham). |
| `flowMode` | `'pressureGradient'` | Default flow-specification mode. |
| `pressureSpecMode` | `'gradient'` | Default pressure-gradient form (direct gradient). |
| `pressureDifference` | `6000` Pa | Default differential pressure `Δp`. |

| `density` | `1000` kg/m³ | Default fluid density `ρ`. |
| `soundSpeed` | `1500` m/s | Default speed of sound `c`. |

### 2.2 `units` — current display unit state

```js
const units = {
  pressure: 'Pa',
  length: 'm',
  velocity: 'm/s',
  flowRate: 'm3/d',
  density: 'kg/m3'
};
```

These four base dimensions drive every conversion. `pressureGradient` and `velocity` are **derived** dimensions:

- `pressureGradient` unit = `<pressure unit>/<length unit>`
- `velocity` unit = `<length unit>/s`

### 2.3 `unitOptions` — conversion factors

| Dimension | Options | `toBase` (multiply to get SI) | Notes |
|-----------|---------|--------------------------------|-------|
| `pressure` | Pa, kPa, psi | `1`, `1000`, `6894.757293168` | — |
| `length` | m, ft, in | `1`, `0.3048`, `0.0254` | — |
| `velocity` | m/s, ft/s, in/s | `1`, `0.3048`, `0.0254` | Independent of `length`; used for velocity labels. |
| `flowRate` | m³/d, bbl/d, MMSCFD, GPM | `1/86400`, `0.158987294928/86400`, `1e6*0.028316846592/86400`, `0.003785411784/60` | Converts volumetric rate to m³/s. |
| `density` | kg/m³, ppg, °API | `1`, `119.826427`, `141.5/(API+131.5)*1000` | °API is a non-linear conversion; reverse uses `141.5/(ρ/1000) - 131.5`. |

### 2.4 Conversion functions

- `toSI(value, dimension, unitValue)` — converts a display value to SI.
- `fromSI(value, dimension, unitValue)` — converts an SI value to the display unit.
- `getUnitLabel(dimension, unitValue)` — returns the label string shown next to a value.

For `pressureGradient` and `velocity` the functions combine the current `pressure`/`length` units, so changing length units automatically updates velocity labels (`m/s → ft/s → in/s`) and pressure-gradient labels (`Pa/m → Pa/ft` etc.).

### 2.5 Reading and writing inputs

- `readDisplay(input, dimension, fallbackSI)` — converts a positive numeric input to SI, falling back to `fallbackSI` if invalid or non-positive.
- `readNonNegativeDisplay(input, dimension, fallbackSI)` — same, but allows zero.
- `readPositive(input, fallback)` — reads a positive number for rheology parameters (no unit conversion).
- `setInputValue(input, value)` — writes a formatted number with `formatNumeric()`, unless the input currently has focus.
- `formatNumeric(value)` — preserves up to 6 significant digits for very small values and strips trailing zeros.
- `formatValue(value, digits)` — user-facing formatter. Uses `toExponential(displaySciDigits)` when `|value| ≥ 10000` or `|value| < 0.001`; otherwise `toLocaleString('pt-BR')` with `digits` decimals. `displaySciDigits` toggles between `2` and `6` when the user clicks any numeric metric value.

### 2.6 Unit change propagation (`applyUnits`)

When the user changes a unit via a `.unit-select`:

1. The old SI values of all numeric inputs are captured.
2. `units[dimension]` is updated.
3. Every input is rewritten with the new-unit equivalent.
4. If a non-homogeneous geometry exists, the geometry textarea is regenerated in the new length unit, the geometry is rebuilt, and the NH calculation is rerun.
5. `refresh()` is called, so every displayed value updates to the new unit.

This means the physical state is preserved; only the displayed numbers and labels change.

## 4. Flow Modes and How `G` and `Q` Are Determined

`#flowMode` selects the independent variable. `#pressureSpecMode` selects the pressure-gradient form.

### 4.1 Pressure-gradient mode (`flowMode === 'pressureGradient'`)

- **`pressureSpecMode === 'gradient'`** — `G` is read directly from `#pressureGradientInput`. `Δp = G L` is computed and shown in diagnostics.
- **`pressureSpecMode === 'differential'`** — `Δp` is read from `#pressureDifference`. `G = Δp / L` is computed. The hidden `#pressureGradientInput` is updated with this value so diagnostics still show `G`.

### 4.2 Flow-rate mode (`flowMode === 'flowRate'`)

`Q` is read from `#flowRateInput`. `G` is found numerically by `solveForG(targetQ, params)` so that `calculate({...params, G}).flowRate === targetQ`.

`solveForG` algorithm:

1. Computes `minG = 2 τ₀ / R` for Bingham/HB (the pressure gradient required to start flow).
2. If `flowRateAtG(minG) ≥ targetQ`, returns `minG` (plugged/no-flow case).
3. Estimates an initial `hi` using `estimateGForQ` and doubles it until the flow rate at `hi` exceeds `targetQ`.
4. Performs bisection between `lo = minG` and `hi` for up to 50 iterations (tolerance `1e-6 * hi`).
5. Returns the average `(lo + hi) / 2`.

`estimateGForQ` uses closed-form approximations derived from the analytical `Q(G)` relations:

- Newtonian / Bingham: `G ≈ (8 K Q) / (π R⁴) + 2τ₀/R`
- Power-Law / Herschel–Bulkley: `G ≈ 2K [ Q(3n+1) / (π n R^((3n+1)/n)) ]^n + 2τ₀/R`

where `K = μ` for Newtonian/Bingham and `K = H` otherwise.

### 4.3 Refresh loop for homogeneous mode (`refresh`)

1. Determine `G` based on mode.
2. `syncYieldStressRange(R, G)` updates the yield-stress slider max.
3. Loop up to 5 times: clamp `τ₀` to the slider max; if flow-rate mode, re-solve `G` with the new `τ₀`.
4. Compute `pressureDifference = G * L`.
5. `updateControls()` updates the visible input fields.
6. `result = calculate(params)`.
7. `updateMetrics(result, ...)` and `updateEquation(result)` update the dashboard and LaTeX.
8. Draw profile chart and flow animation.

## 5. Rheological Models and the `calculate()` Pipeline

### 5.1 Common definitions

For all models:

```
τ_w = G R / 2                         # wall shear stress
flowing = (no yield) OR (τ_w > τ₀)
Pl = τ₀ / τ_w = R_p / R               # plasticity index (0 for no-yield models)
R_p = Pl * R                          # plug radius
```

`calculate(model, R, G, mu, H, n, tau0)` builds 201 radial samples (`x = r/R`, `r = x R`) and returns:

| Return field | Meaning |
|--------------|---------|
| `params` | The input parameter object (including `G`). |
| `G`, `tauW`, `tau0` | Pressure gradient, wall shear stress, yield stress. |
| `flowing` | Boolean indicating whether `τ_w` exceeds `τ₀` (for yield-stress fluids). |
| `Pl`, `Rp` | Plasticity index and plug radius. |
| `samples` | 201 radial points `{x, r, velocity, stress, shearRate}`. |
| `maxVelocity` | Maximum velocity (centerline for fully flowing cases). |
| `meanVelocity` | `Q / (π R²)`, the bulk average velocity. |
| `flowRate` | `Q` computed by the closed-form Herschel–Bulkley integral. |
| `wallShearRate` | Exact wall value: `((ℵ_w - ℵ_0) / K)^(1/n)` for HB/PL, `(ℵ_w - ℵ_0) / µ` for Bingham, `ℵ_w / µ` for Newtonian. |

### 5.2 Velocity profiles

#### Newtonian (`model === 'newtonian'`)

```
τ_rz = μ dU/dr
U_z(r) = G (R² - r²) / (4 μ)
Q = π G R⁴ / (8 μ)
```

Parabolic profile, maximum at `r = 0`.

#### Power-Law (`model === 'powerLaw'`)

```
τ_rz = H (-dU/dr)^n
U_z(r) = (n R / (n+1)) (τ_w / H)^(1/n) [1 - (r/R)^((n+1)/n)]
```

- `n < 1`: pseudoplastic (shear-thinning), flatter profile.
- `n = 1`: reduces to Newtonian with `H = μ`.
- `n > 1`: dilatant (shear-thickening), sharper profile.

#### Bingham (`model === 'bingham'`)

```
Pl = τ₀ / τ_w
R_p = Pl R
```

For `r ≤ R_p` (unyielded plug):

```
U_z(r) = (R τ_w / (2 μ)) (1 - Pl)²
```

For `R_p < r ≤ R`:

```
U_z(r) = (R τ_w / (2 μ)) [(1 - Pl)² - (r/R - Pl)²]
shearRate = (τ - τ₀) / μ
```

The analytical flow rate is:

```
Q = π G R⁴ / (8 μ) [1 - (4/3) Pl + (1/3) Pl⁴]
```

#### Herschel–Bulkley (`model === 'herschelBulkley'`)

```
factor = (n R / (n+1)) (τ_w / H)^(1/n)
```

For `r ≤ R_p`:

```
U_z(r) = factor (1 - Pl)^((n+1)/n)
```

For `R_p < r ≤ R`:

```
U_z(r) = factor [(1 - Pl)^((n+1)/n) - (r/R - Pl)^((n+1)/n)]
shearRate = ((τ - τ₀) / H)^(1/n)
```

The displayed flow-rate formula in the equation card is the integrated analytical expression.

### 5.3 Flow-rate integration

The code does not rely on the closed-form `Q` for results; it computes `flowRate` numerically:

```js
areaIntegral = Σ 0.5 (v_i r_i + v_{i+1} r_{i+1}) (r_{i+1} - r_i)
Q = 2 π areaIntegral
V = Q / (π R²)
```

This guarantees consistency between the profile, `V`, and all Reynolds/Mach numbers.

## 6. Diagnostics and Displayed Values (`updateMetrics`)

`updateMetrics(result, mode)` computes the dashboard diagnostics from `result` (the object returned by `calculate`).

### 6.1 Primary metric cards

| Card | Source | Unit | Formula/Notes |
|------|--------|------|---------------|
| `U_max` | `result.maxVelocity` | velocity | Centerline velocity. |
| `U` (mean) | `result.meanVelocity` | velocity | `V = Q / (π R²)`. |
| `Q` | `result.flowRate` | flowRate | Volumetric flow rate. |
| `τ_w` | `result.tauW` | pressure | `G R / 2`. |

### 6.2 Diagnostic list

| Diagnostic | Symbol | Calculation |
|------------|--------|-------------|
| `G` | `G` | `params.G` (shown as pressure unit / length unit). |
| `Δp` | `Δp` | `params.G * params.tubeLength`. |
| `Pl` | `Pl` | `τ₀ / τ_w` (0 if `τ₀ = 0`). |
| `R_p` | `R_p` | `Pl * R` (shown only if `τ₀ > 0`). |
| `A_nc` | `A_nc` | `Pl² * 100` as a percentage. |
| `γ̇_w` | `γ̇_w` | `((3n+1)/(4n)) * (8 V / D)`. |
| `Re` | `Re` | `8 ρ V² ((3n+1)/(4n)) / [τ₀ + K ((3n+1)/(4n))^n (8V/D)^n]` |
| `m` | `m` | `n K γ̇_w^n / τ_w` (with `η_∞ = 0`). |
| `Re_HBE` | `Re_HBE` | `ρ V^(2-n) D^n / [ (τ₀/8)(D/V)^n + K ((3m+1)/(4m))^n 8^(n-1) ]` |
| `f_D` | `f_D` | `64 / Re_HBE` if `Re_HBE ≤ 2100`; otherwise solved from the Dodge–Metzner implicit equation. |
| `Δp_DW` | `Δp_DW` | `f_D (L/D) (ρ V² / 2)`. |
| `Ma` | `Ma` | `V / c`. |

In the formulas above:

- `V` = `result.meanVelocity` (`m/s`).
- `D` = `2 R`.
- `n` = flow index for Power-Law/HB, `1` for Newtonian/Bingham.
- `K` = `μ` for Newtonian/Bingham, `H` for Power-Law/HB.
- `m` = local flow-behavior index, clamped to `[0.1, 1]` for the turbulent friction correlation.

### 6.3 Dodge–Metzner Darcy friction factor

For `Re_HBE > 2100`, the code solves the implicit equation:

```
1/√f_D = (2 / m^0.75) log10[ Re_HBE (f_D / 4)^(1 - m/2) ] - 0.2 / m^1.2
```

by fixed-point iteration on `y = 1 / √f_D`. For `m = 1` this reduces to the Prandtl–Nikuradse smooth-pipe equation.

### 6.4 Flow-state badge

The badge at the top right is determined by:

```js
flowing = result.flowing && result.maxVelocity > 0
turbulent = reHbe > 2100
supersonic = mach > 1
```

Possible states: `Sem escoamento`, `Escoando`, `Turbulento`, `Supersônico`, `Turbulento / Supersônico`.

## 7. Non-Homogeneous Duct

### 7.1 Geometry input

`#geometryInput` accepts two columns of numbers: axial position `x` and local radius `r`. Values are sanitized to allow only digits, whitespace, signs, exponents, and decimal points. The parser:

1. Splits on whitespace.
2. Requires an even number of tokens (at least 4).
3. Converts both columns to SI length using the current length unit.
4. Sorts by `x`.
5. Validates `x` strictly increasing and `r > 0`.

### 7.2 Profile interpolation

`#profileMode` chooses `linear` or `cubic`:

- **Linear**: `r(x) = r_i + t (r_{i+1} - r_i)` with `t = (x - x_i) / (x_{i+1} - x_i)`.
- **Cubic**: monotone Fritsch–Carlson (PCHIP) interpolation; avoids overshoot and negative radii. Falls back to linear if fewer than 3 points.

`radiusAt(points, x, mode)` returns `max(1e-6, interpolatedRadius)` to avoid division-by-zero at extremely narrow sections.

### 7.3 Subdivision

`buildSubsections(points, subdivisions, mode)` creates `N` constant-radius subsections **per original segment**, where `N` is capped so the total number of subsections does not exceed 2,000; the user-supplied value is automatically reduced when necessary. Each subsection stores:

- `xLeft`, `xRight`, `xCenter`
- `r` = `radiusAt(points, xCenter, mode)`
- `dx = xRight - xLeft`
- `segmentIndex` (which original segment it belongs to)

The displayed `Seções N` is the total number of subsections.

### 7.4 Calculation

`calculateNonHomogeneous()`:

1. Reads current global parameters.
2. Determines the global flow rate `Q`:
   - **Flow-rate mode**: `targetQ = baseParams.flowRate`.
   - **Pressure-gradient mode**: `targetP = Δp` or `G * L`. `targetQ = solveGlobalQ(targetP, baseParams, subsections)`.
3. For each subsection, `solveSection(baseParams, R_i, dx_i, {flowMode: 'flowRate', targetQ})` computes the local `G_i` and `dp_i = G_i dx_i`.
4. `totalPressure = Σ dp_i`.
5. `avgRadius = sqrt( (Σ r_i² dx_i) / L )` — the area-averaged (RMS) radius.
6. `avgArea = π avgRadius²`.
7. `avgVelocity = targetQ / avgArea` (0 if no flow).
8. `avgMach = avgVelocity / soundSpeed`.
9. `reMax` and `reMedian` are computed from the per-subsection Reynolds numbers.
10. `segmentResults` are built per original segment for the detail table.

### 7.5 Solving for global `Q` in pressure-gradient mode

`solveGlobalQ(targetP, baseParams, subsections)`:

1. Computes `thresholdPressure = Σ (2 τ₀ / r_i) dx_i`. If `targetP ≤ thresholdPressure`, flow is below the yield threshold → `Q = 0`.
2. Estimates `Q` analytically with `estimateFlowRateForPressure`.
3. Brackets `Q` by doubling until `totalPressureForQ(hi) ≥ targetP`.
4. Refines with the secant method (40 iterations, tolerance `1e-4 * targetP`).

`totalPressureForQ(Q, ...)` sums `G_i(Q) dx_i` for all subsections, where each `G_i` is found by `solveForG`.

`verifyNHResults()` logs the maximum subsection flow-rate error and total pressure error to the console for sanity checking.

### 7.6 Non-homogeneous results panel

| Card | Source | Unit | Notes |
|------|--------|------|-------|
| `Δp total` | `totalPressure` | pressure | Sum of subsection pressure drops. |
| `Raio médio R` | `avgRadius` | length | Area-averaged RMS radius. |
| `Velocidade média U` | `avgVelocity` | velocity | `Q / (π avgRadius²)`. |
| `Reynolds máximo` | `reMax` | — | Largest subsection `Re`. |
| `Reynolds mediano` | `reMedian` | — | Median subsection `Re`. |
| `Mach médio` | `avgMach` | — | `avgVelocity / c`. |
| `Seções N` | `subsections.length` | — | Total number of subsections. |

The per-section table (`Seções individuais`) lists each original segment with `x`, `Δx`, `R` (center subsection), `U` (mean velocity), `Re`, and `Δp`.

## 8. Visualization

### 8.1 Homogeneous mode

- **Radial profile chart (`#profileCanvas`)**: draws `U(r/R)` (cyan) and `τ(r/R)` (amber dashed). The plug region is highlighted in violet when `τ₀ > 0`. Hovering shows `r/R`, `U`, `τ`, and `γ̇` at that point.
- **Longitudinal flow canvas (`#flowCanvas`)**: a color-coded pseudo-3D duct view. Particle speed depends on the local velocity ratio `U(y/R) / U_max`.

### 8.2 Non-homogeneous mode

- **Duct profile (`#ductProfileCanvas`)**: plots `r` vs `x`, the original data points, and vertical subdivision boundaries.
- **Duct flow (`#ductFlowCanvas`)**: draws the tapered duct and animates particles. Each particle's horizontal speed is proportional to the local mean velocity of the subsection it currently occupies, so narrower (faster) sections accelerate particles visibly.

### 8.3 Animation

`requestAnimationFrame` drives `animate(timestamp)`. `delta` is the frame time in milliseconds. The flow canvases recompute particle positions each frame; the profile chart is redrawn only on hover or resize.

## 10. Scenario Behavior

### 10.1 No-flow cases

- **Homogeneous yield-stress fluid**: if `τ_w ≤ τ₀`, `flowing` is false. Velocity profile is zero everywhere, `Pl = 1`, badge shows `Sem escoamento`.
- **Non-homogeneous pressure-gradient mode**: if `targetP ≤ thresholdPressure`, `solveGlobalQ` returns `0`. All NH metrics become zero and the badge shows `Sem escoamento`.

### 10.2 Unit changes

Changing a unit preserves the physical state:

- Inputs are converted to the new unit.
- All metric/diagnostic values are re-displayed in the new unit.
- Equations stay in SI (a note in the UI informs the user of this).
- NH geometry is regenerated in the new length unit.

### 10.3 Model changes

Switching rheological models:

- Hides/shows the relevant parameter inputs.
- Updates the model description and equation cards.
- Recomputes `G`/`Q` and all diagnostics.
- Marks NH results as dirty (requires recalculation).

### 10.4 Pressure-gradient vs flow-rate modes

- **Pressure-gradient (direct)**: `G` is fixed; `Q`, `U`, `Re`, `Ma` respond to rheology/geometry changes.
- **Pressure-gradient (differential)**: `Δp` is fixed; `G` is derived as `Δp/L`; behaves like direct gradient for downstream calculations.
- **Flow-rate**: `Q` is fixed; `G` is solved iteratively; increasing viscosity/yield stress increases `G` and `Δp`.

### 10.5 Non-homogeneous convergence

Increasing `Subdivisões por trecho` refines the integration:

- `totalPressure` converges as more subsections are used.
- `avgRadius` is already an area-averaged value and converges quickly.
- `avgVelocity` depends on `targetQ` and `avgRadius`; for a fixed `Q`, it is physically consistent.
- `Re` per subsection depends on the local radius and the common `Q`.

### 10.6 Extreme inputs

- Very small radius: `radiusAt` clamps to `1e-6` m, preventing `Infinity`/`NaN`.
- Very high `G` or `Q`: `solveForG` and `solveGlobalQ` cap iterations and bracket up to `1e12` to avoid runaway loops.
- Very low density or sound speed: `Mach` and `Re` gracefully handle zero/negative denominators by returning `0`.
